MsgUserInfo (1006) and others.

Wire format, at *(list + 4):
  [count:u8] then repeated [length:u8][bytes...]
The routine skips the count byte (`*(list+4) + 1`), gets the entry count from sub_771FC0, and
walks entries advancing by `length + 1`.

BOUNDS CONTRACT (important for server writers):
  memset(dest, 0, destSize) happens FIRST, then
  if (destSize <= length) -> break and return 0
So an entry is copied only when `length < destSize`. With the 0x10 buffers used by 1006 and by
MsgTalk indices 0..2, the maximum usable entry length is 15 bytes. A 16+ byte entry is NOT
truncated -- it is skipped entirely and the destination stays zeroed, so an over-long name
silently renders blank instead of failing. Servers must reject over-long entries themselves.
