# CP3.2c account and world-entry wire paths

2026-11-08. Source audit from [client main](https://github.com/berniemackie97/OpenConquerClient/tree/3f38c69c5251011765a895bc15c59f0ae8d3e336) and [server main](https://github.com/berniemackie97/OpenConquerServer/tree/8b0f0745332a29530d046a44104ccf6d2914e62a). Reviewed production callers and ingress dispatch from account connection through world activation. The account catalog trust envelope and post-activation simulation are separate boundaries. This extends the [named-codec census](https://github.com/berniemackie97/OpenConquerClient/blob/3f38c69c5251011765a895bc15c59f0ae8d3e336/docs/networking/wire-evidence-inventory.md).

Source evidence labels refer to [the two Windows VM sessions](../cp32-world-entry-2026-11-08/README.md). Native exact means bytes emitted by the original client. Peer means controlled server-originated input. Metadata means the payload was withheld at collection. Source-only means this VM trace did not exercise the path.

## Existing-character world activation

| Wire identity | Active call sites and behavior | Evidence |
|---|---|---|
| 2078, 2079, 1006 S→C | ExistingCharacterBootstrapProcessor sends login history, server state and user info after 1004. LoginAttemptCoordinator and RoleCreationExchange use GameServerHandshakeSession prelude and character readers before GameWorldEntryBootstrap. | Peer packets. Blank 2078 exact in run 2. Native proceeded to EnterMap and rendered the hero. |

| 1134/3 C→S | The original client emits this burst after ANSWER_OK. OCS LoginActionRequest accepts it while awaiting 74 or 75, validates/discards it and sends no reply. A production search of OCC main found no 1134 writer or dispatcher route. The named-codec inventory's client entry conflates retail behavior with managed support. | Native lengths/order in run 1, native exact in run 2. See verification below. |
| 10010/114, 75, 76, 96, 77, 78, 97, 251, 132 C→S | GameWorldEntryBootstrap sends 114 then 75 after ACK 74, 76 then PK mode 96 after ACK 75, and the remaining requests on their ACKs. GameWorldAction10010.Write packs 96 mode 3 at +8, matching native. 251 uses entity 0, checksum at +8 and version at +16. LoginActionRequest skips valid non-ladder actions such as 114 and 96. ExistingCharacterStatisticsRequestProcessor ends admission on 132 without replying. | Exact native sequence including 96 and 251. Peer ladder ACKs. |
| 1008 and 1009/46 S→C | ExistingCharacterItemSetProcessor projects 1008 item records and the optional 1009/46 active-equipment snapshot before ACK 75. GameWorldEntryBootstrap stores them for WorldInboundState to replay through GameWorldPacketDispatcher. | The empty test hero produced no item snapshots. Source-only. |
| 1019, 1025, 1103, 1104, 1106 S→C | Existing-character friend, weapon skill, magic and syndicate processors emit content before ACKs 76–78 and 97. The magic processor optionally adds 1104 with its magic discriminator. OCC queues these frames in bounded hydration storage, then the dispatcher sends these IDs to its unknown handler. | Source-only for populated hydration. No claim of managed client presentation. |
| 1009/27 C→S / S→C | LoginActionRequest can echo it during bootstrap, and GameConnectionWorkerPool echoes it in world. OCC's WorldFrameEgress starts its heartbeat from the EnterMap exchange. | Exact native packets and controlled echoes after admission. Raw timer mismatch is tracked in [client #299](https://github.com/berniemackie97/OpenConquerClient/issues/299). |

The account TCP writes converge on LoginAccountSession and the server's LoginFrameWriter. Game logical packets converge on GameServerHandshakeSession.WriteSecuredPacketAsync and the server's GameSecuredFrameWriter. The DH envelope uses the separate bootstrap path. No additional untyped 5517 serializer was found inside this entry boundary. Bounded hydration is an explicit untyped transfer of already framed bytes, with typed parsing deferred to WorldInboundState. Post-activation producers, readers and the full per-message variant census remain open.

## 1134 verification

Capture 2 frames 13–15 match every byte generated by the server fixture's ID ranges and little-endian record layout. Sizes are 968, 968 and 776. The older fixture names the clean 5517 Questinfo.ini. The VM used a copy from 5517-loader and launched the verified retail executable directly. The two Questinfo.ini files have different SHA-256 values. Parsing both shows the same 230 MissionId rows and the same sorted set of 224 unique IDs. The capture and fixture match for the whole burst. [Comparison and digests](mission-catalog-verification.json)

Run 1 placed the contiguous burst after 74 and 1151/2 but before 75. Run 2 placed it before 74 and 1151/2. Both fit the OCS window. Existing server tests exercise admission with both placements and reject a split burst. The VM used a controlled peer, while the server tests exercise managed policy.

Native Conquer.exe view 9. CQuestTaskTypeMgr_SendMissionCatalogOnLogin iterates the ascending mission map at +0x18. On a full frame, 0x6A588F sends, 0x6A589A resets, and 0x6A58A8 retries the same ID. ResetEntries at 0x72D589 clears count +6 and sets length to 4. It leaves the body intact. The initial 0x400-byte reset zeroes the reused storage. AppendEntry writes the ID and zero state word. The other record bytes remain zero in this catalog path. At 0x6A4F78 the manager looks up a signed MissionId, returning node+0x14 or null on the end sentinel. Binary Ninja name and comments were updated in the active database.
